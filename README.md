# ViTube TH

**ViTube ที่อ่านภาษาไทยได้** — แอป YouTube สำหรับ PlayStation Vita
ฉบับนี้ fork มาจาก [**ViTube** ของ shorelight82](https://github.com/shorelight82/vitube-vpk)
เพิ่มการแสดงผลภาษาไทย ระบบดาวน์โหลดวิดีโอไว้ดูออฟไลน์ และปรับการใช้งานบางส่วนให้ลื่นขึ้น

> ตัวแอปทั้งหมดเป็นผลงานของ **shorelight82** ได้แก่ หน้าแรก การค้นหา
> ช่องที่ติดตาม การล็อกอิน การเล่นวิดีโอ 720p ด้วยฮาร์ดแวร์ของ Vita และระบบเครือข่าย
> fork นี้เพิ่มเฉพาะส่วนที่ระบุในหัวข้อ [สิ่งที่ fork นี้เพิ่ม](#สิ่งที่-fork-นี้เพิ่ม)
> ถ้าชอบแอปนี้ กรุณาไปกดดาวให้
> [repo ต้นทาง](https://github.com/shorelight82/vitube-vpk) ด้วยครับ

### วิธีติดตั้ง

1. Vita ต้องลง HENkaku/Ensō ไว้แล้ว
2. โอนไฟล์ `ViTube-TH.vpk` เข้า Vita ผ่าน VitaShell (FTP หรือ USB)
3. ใน VitaShell กด ✕ ที่ไฟล์เพื่อติดตั้ง
4. เปิดแอป ไปที่แท็บ **More → Region → ประเทศไทย**

**หมายเหตุ:** แอปนี้ใช้ Title ID เดียวกับ ViTube ต้นฉบับ (`VTUB00001`)
จึงติดตั้งทับ ViTube ตัวเดิม การล็อกอินและประวัติที่เก็บใน `ux0:data/ViTube/`
ยังอยู่ครบ ถ้าอยากกลับไปใช้ตัวต้นฉบับ ให้ลง VPK จาก
[Release ของต้นทาง](https://github.com/shorelight82/vitube-vpk/releases) ทับได้เลย

ถ้าอัปเดตมาจาก ViTube เวอร์ชัน 1.2 หรือเก่ากว่า ให้รีบูตเครื่องหนึ่งครั้งหลังติดตั้ง
(รายละเอียดอยู่ใน [README ต้นฉบับ](README.upstream.md#installing-on-the-vita))

### ใหม่ในเวอร์ชัน 2.11 — โหลดเพิ่มได้ทุกหน้า (issue #10 ของต้นทาง)

[Issue #10](https://github.com/shorelight82/vitube-vpk/issues/10) ของต้นทางรายงานว่าหน้า Start หยุดที่ราว 60 คลิป
เลื่อนลงสุดแล้วไม่มีอะไรเกิดขึ้น เหตุผลมีหลายชั้น และชั้นลึกสุดเพิ่งเจอตอนลองกับ YouTube จริง:

| ก่อน | หลัง |
|---|---|
| token ของหน้าถัดไปยาว 4,000–13,000 ตัวอักษร แต่ buffer เก็บได้ 2,048 จึงถูกทิ้งเงียบๆ | เก็บได้ถึง 24,576 (token โตหน้าละราว 2–3 KB) |
| รายการต่อหน้าเก็บได้ 60 แถว ทั้งที่ YouTube ส่งมา 58–84 แถว ส่วนที่เกินหายไปถาวร | เก็บได้ 128 แถวต่อหน้า |
| ขอหน้าถัดไปจาก endpoint ค้นหาเสมอ | ส่งกลับไปที่ endpoint และ client เดียวกับที่ออก token (Start, ค้นหา, รายการวิดีโอในช่อง) |
| token ผูกกับ visitor id ของ response ที่ออกมัน ถ้าส่งโดยไม่มี id หรือใช้ id อื่น YouTube ตอบ 200 แต่ว่างเปล่า และตัวกรอง `fields` ของแอปตัด id นั้นทิ้งตั้งแต่ต้น | ขอ `responseContext/visitorData` เพิ่มในตัวกรอง เก็บ id ไว้กับรายการ แล้วส่งกลับทุกครั้ง แม้จะมีการเรียกอื่นที่เปลี่ยน id ทั่วระบบคั่นกลาง (เช่น ตอนเล่นวิดีโอ) |
| โหลดเพิ่มได้เฉพาะผลค้นหา และถ้าล้มเหลวครั้งเดียวก็หยุดถาวร | Start, ค้นหา และรายการวิดีโอในช่องโหลดเพิ่มได้ ล้มเหลวแล้วเก็บ token ไว้ให้ลองใหม่ (3 ครั้งติดกันจึงหยุด) |

พฤติกรรมที่เห็นบนเครื่อง: เลื่อนลงจนสุดรายการ (D-pad กดลงที่แถวสุดท้าย หรือเลื่อนนิ้วจนสุด) จะขึ้น "Loading more"
แล้วรายการยาวขึ้น ฟีดของ YouTube จบที่ราว 5 หน้า (ประมาณ 150–200 คลิปไม่ซ้ำ) และรายการหนึ่งเก็บได้สูงสุด 240 แถว
ถ้าหน้าที่ขอมาไม่มีวิดีโอใหม่เลย จะขึ้น "No more videos" หนึ่งครั้ง

**ข้อจำกัด**: Start ตอน**ล็อกอิน**และฟีด **Subs** ยังโหลดเพิ่มไม่ได้ เพราะรูปแบบข้อมูลของสองส่วนนี้ต้องยืนยันด้วยบัญชีจริง
(ฟีด Subs มี token หลายตัวต่อหน้า และตัวแรกต่อได้แค่ชั้นเดียว) จึงปิดไว้ก่อนแทนการเดา
ถ้าคุณล็อกอินอยู่และอยากให้เปิด ส่ง `ux0:data/ViTube/log.txt` ตอนเลื่อนสุดรายการมาที่ Issues ได้
บรรทัด `parse ...: continuation=... surface=...` จะบอกว่า token มาแบบไหน

### ใหม่ในเวอร์ชัน 2.10 — ดาวน์โหลดวิดีโอ

บันทึกวิดีโอลงการ์ดความจำ (`ux0:data/ViTube/downloads/`) แล้วเปิดดูได้โดยไม่ต้องใช้เน็ต

- **เมนูดาวน์โหลด**: กด **SELECT** บนรายการวิดีโอ (หน้าแรก ค้นหา ช่องที่ติดตาม ช่อง ประวัติ)
  แล้วเลือก "Download" บนหน้าจอสัมผัสกดค้างที่รายการ 0.6 วินาทีก็เปิดเมนูได้
  เมนูบอกพื้นที่ว่างบนการ์ดไว้ที่หัวเมนู และถ้าการ์ดแทบเต็มจะแจ้งก่อนเริ่มโหลด
- **แท็บ Downloads** (ใหม่ อยู่ระหว่าง Subs กับ More): แสดงคิวและที่โหลดเสร็จแล้ว
  แต่ละรายการมีสถานะ แถบความคืบหน้า ขนาด ความเร็ว ด้านบนแสดงพื้นที่ว่างบนการ์ด
  (สีแดงเมื่อการ์ดเต็ม) และมีตัวเลขจำนวนที่กำลังโหลดบนแท็บ
- **หยุดชั่วคราว / ต่อ / ลองใหม่ / ลบ** รายการเดียวหรือทั้งหมด (SELECT บนแท็บ Downloads)
  ส่วน ✕ จะทำสิ่งหลักของรายการนั้น เช่น เล่นเมื่อโหลดเสร็จ หยุดเมื่อกำลังโหลด
- **โหลดต่อจากที่ค้างเมื่อเน็ตหลุด**: โหลดเป็นช่วงละ 4 MB ถ้า Wi-Fi หลุดหรือเครื่องหลับ
  จะรอแล้วโหลดต่อจากไบต์ที่ได้มาแล้ว ไม่เริ่มใหม่ ถ้า URL ของ YouTube หมดอายุ
  จะขอใหม่เองและโหลดต่อ (ถ้าไฟล์เปลี่ยนจะเริ่มใหม่)
- **ตรวจว่าไฟล์ถูกต้อง** ก่อนนับว่าโหลดเสร็จ: ขนาดต้องตรงกับที่เซิร์ฟเวอร์บอก และโครงสร้างไฟล์ MP4
  ต้องสมบูรณ์ (ftyp, moov, mdat และขนาดกล่องลงตัวกับขนาดไฟล์) ไฟล์ที่เสียจะถูกลบและโหลดใหม่ได้
- **เช็กที่ว่างก่อนโหลด**: ต้องมีที่ว่างพอสำหรับไฟล์ บวกสำรองไว้อีก 128 MB
  ถ้าไม่พอจะขึ้น "Needs X, only Y free" โดยเก็บส่วนที่โหลดไปแล้วไว้ พอลบของแล้วกดลองใหม่ก็โหลดต่อได้
- **เล่นออฟไลน์**: เลือกวิดีโอที่โหลดแล้ว เครื่องจะเล่นจากไฟล์ในการ์ดโดยไม่ต่อเน็ตเลย
  (กรอได้ ปรับเสียงได้) จากหน้าแรกหรือค้นหาก็เล่นจากไฟล์ที่โหลดไว้ให้อัตโนมัติ
  ถ้าไฟล์เล่นไม่ได้ จะแจ้งว่าไฟล์เสียแล้วดูแบบสตรีมแทนเมื่อมีเน็ต
- ระหว่างดูวิดีโอแบบออนไลน์ การดาวน์โหลดจะหยุดรอ เพื่อไม่แย่งความเร็วจากวิดีโอที่กำลังดู

ข้อจำกัด: ดาวน์โหลดได้ที่ **360p** เท่านั้น (ขนาดที่ YouTube ให้เป็นไฟล์เดียวมีภาพและเสียงรวมกัน)
720p เป็น HLS ที่แบ่งท่อนและแยกเสียง ยังไม่รองรับ และไลฟ์สดโหลดไม่ได้
การดาวน์โหลดวิดีโอ YouTube อาจขัดกับข้อกำหนดการใช้งานของ YouTube
ควรใช้กับวิดีโอที่คุณมีสิทธิ์เก็บไว้ดูเท่านั้น

## ทำงานอย่างไร (สำหรับนักพัฒนา)

แอปวาดตัวอักษรด้วย vita2d ซึ่งวาดทีละตัวโดยไม่มีระบบจัดวางตัวอักษร (shaping)
และไม่อ่านตาราง GSUB/GPOS ในฟอนต์ ขณะที่ภาษาไทยต้องใช้ตารางเหล่านี้
เพื่อยกวรรณยุกต์ขึ้นเหนือสระบน เลื่อนเครื่องหมายบน ป ฝ ฟ ไปทางซ้าย
และตัดเชิง ญ ฐ เมื่อมีสระล่าง

fork นี้จึงย้ายการ shaping ไปทำตอน build แทนตอนรันแอป:

1. [`tools/make-thai-font.py`](tools/make-thai-font.py) ใช้ HarfBuzz จัดวางทุกกลุ่มอักษร
   (พยัญชนะ + สระบน/ล่าง + วรรณยุกต์ + สระอำ) ของ Noto Sans Thai
   ผลที่ต่างจากการวาดทีละตัวจะถูกบันทึกเป็น glyph ประกอบในช่วง Private Use Area
   ของ [`assets/thai.ttf`](assets/thai.ttf) (ปัจจุบันมี 2,268 กลุ่ม)
   และสคริปต์จะสร้างตาราง [`src/ui/thai_shape_table.h`](src/ui/thai_shape_table.h) ไปพร้อมกัน
2. ตอนรันแอป [`src/ui/thai_shape.c`](src/ui/thai_shape.c)
   จะเปลี่ยนข้อความไทยให้เป็น code point ของ glyph เหล่านั้น
   ทำให้ vita2d วาดออกมาถูกต้องโดยไม่ต้องจัดตำแหน่งเพิ่ม
   ผลลัพธ์ไม่ยาวกว่าข้อความเดิม จึงใช้บัฟเฟอร์ขนาดเท่าข้อความเดิมได้
3. [`src/ui/ui.c`](src/ui/ui.c) ใช้ `thai.ttf` เป็นฟอนต์สำรองตัวที่สาม
   ต่อจาก DejaVu Sans และ Noto Emoji ที่ต้นทางใช้อยู่แล้ว
   และขยายกรอบตัดข้อความแนวตั้ง เพื่อไม่ให้วรรณยุกต์ที่ซ้อนสูงหรือสระล่างโดนตัด

ส่วนอื่นที่แก้: เพิ่มภูมิภาค `th/TH` ใน [`src/yt/region.c`](src/yt/region.c)
และเพิ่มคำบอกเวลาภาษาไทยใน `age_minutes()` ของ [`src/yt/parse.c`](src/yt/parse.c)

ถ้าต้องการสร้างฟอนต์ใหม่ (เช่น ตอนเปลี่ยนเวอร์ชัน Noto Sans Thai):

```sh
pip install fonttools uharfbuzz
python3 tools/make-thai-font.py NotoSansThai-Regular.ttf
```

ต้องสร้าง `assets/thai.ttf` และ `src/ui/thai_shape_table.h` ใหม่พร้อมกันเสมอ
URL และ sha256 ของฟอนต์ต้นฉบับอยู่ในหัวไฟล์สคริปต์

### ระบบดาวน์โหลด (2.10)

แยกเป็นชั้น เพื่อให้ตรรกะทั้งหมดทดสอบบนคอมได้โดยไม่ต้องมี Vita:

- [`src/dl/dl.h`](src/dl/dl.h) คือ API กลางที่ UI และ player เรียกใช้ (ไม่บล็อกการวาดเฟรม)
- [`src/dl/dl_core.c`](src/dl/dl_core.c) คือคิวกับ state machine ของแต่ละรายการ
  ทุกอย่างที่แตะโลกภายนอก (ไฟล์ เครือข่าย เวลา) ผ่าน `ops` ที่สลับเป็นของปลอมตอน test ได้
  [`dl_index.c`](src/dl/dl_index.c) อ่านเขียน `index.json` (ถือเป็นข้อมูลที่ไม่น่าไว้ใจ
  ตรวจ id และความยาวทุกค่า) และ [`dl_mp4.c`](src/dl/dl_mp4.c) ตรวจกล่องของไฟล์ MP4
- [`src/dl/dl.c`](src/dl/dl.c) คือส่วนที่ผูกกับ Vita: thread ทำงาน การเขียนไฟล์ทีละ 128 KB
  ภายใต้ `vt_io_lock` (ทั้งแอปใช้ล็อกเดียวกันเพราะเคยเกิดอาการเครื่องค้างจากการเรียก SceIo พร้อมกัน)
  การถามพื้นที่ว่างด้วย `sceAppMgrGetDevInfo` และการขอ URL ด้วย `yt_resolve_stream`
- [`src/media/local_stream.c`](src/media/local_stream.c) ให้ตัวถอดรหัสอ่านไฟล์ในการ์ด
  โดยมีบัฟเฟอร์อ่านล่วงหน้าต่อ cursor
- `external/vita-https` ถูกแก้เล็กน้อย: `VitaHttpsRequest` มี callback เพิ่ม 2 คู่ (`on_response` อ่านสถานะ
  Content-Length และ Content-Range ก่อนเริ่มรับข้อมูล, `should_abort` ตัดคำขอที่ socket ตายระหว่างเครื่องหลับ)
  ฟิลด์ใหม่เป็นศูนย์ได้ ผู้เรียกเดิมจึงทำงานเหมือนเดิมทุกประการ

### การโหลดต่อ / continuation (2.11)

- [`src/yt/model.h`](src/yt/model.h): `yt_surface_t` บอกว่า token ของหน้านั้นออกจากคำขอแบบไหน
  (`SEARCH`, `BROWSE_WEB`, `CHANNEL_TV`, หรือ `NONE` = ห้ามโหลดต่อ) และ `yt_video_list_t` เก็บ token, surface และ visitor id ไปด้วยกัน
- [`src/yt/innertube.c`](src/yt/innertube.c): ตารางเส้นทางเดียวใช้ทั้งตอนส่ง `yt_continue()` และตอนระบุ surface ให้หน้าที่ได้มา
  ทุกจุดเรียกระบุ surface ตรงๆ ไม่เดาจากพารามิเตอร์ ถ้าคำขอที่ส่งจริงไม่ตรงกับแถวของ surface นั้นจะถือเป็น `NONE`
- [`src/ui/list_screen.c`](src/ui/list_screen.c): `load_more()` ตัวเดียวสำหรับ D-pad และการเลื่อนนิ้วจนสุด
  ใช้ task ที่ถือสำเนา token/surface/visitor ไว้ ไม่ให้ตัวลองใหม่อ่านค่าที่ถูกแก้ระหว่างทาง
- ตรวจกับของจริง: ชุดทดสอบยิง YouTube จริงผ่านโค้ดจริงของ `innertube.c` และ `parse.c`
  ตั้งแต่หน้า 1 ถึง 5 ของ Start, รายการในช่อง และผลค้นหา รวมกรณีเล่นวิดีโอคั่นกลางแล้วเลื่อนต่อ
  ผลที่จับไว้เป็น fixture ใน `tests/fixtures/` (`browse_home_visionos_page2..4*.json`, `channel_uploads_tv*.json`)

### การเลื่อนด้วยนิ้ว (2.01)

เดิมรายการเก็บตำแหน่งเลื่อนเป็นเลขแถว และรับรู้การลากนิ้วตอนปล่อยนิ้วเท่านั้น
จึงขยับทีละ 3 แถว ตอนนี้ [`src/ui/kinetic_scroll.c`](src/ui/kinetic_scroll.c)
เก็บตำแหน่งเป็นพิกเซล และคำนวณการลาก ความเร็วตอนปล่อย การไหลต่อแบบหน่วงตามเวลาจริง
การเด้งกลับ และการเลื่อนนุ่มๆ เมื่อใช้ D-pad
โมดูลนี้ไม่ขึ้นกับ Vita จึง test บนคอมได้
[`src/ui/list_screen.c`](src/ui/list_screen.c) วาดแถวตามตำแหน่งพิกเซล
ส่วน [`src/ui/rows_view.c`](src/ui/rows_view.c) ตัดขอบแต่ละแถวไม่ให้ทับแถบแท็บ

### การเชื่อมต่อใหม่หลังปลุกเครื่อง (2.01)

พอ Vita เข้าโหมดพัก socket ทั้งหมดจะถูกปิด และ Wi-Fi ใช้เวลาหลายวินาทีกว่าจะกลับมา
- [`src/net/netwatch.c`](src/net/netwatch.c) รันใน thread แยก
  ตรวจว่าเครื่องเพิ่งตื่น (เวลานาฬิกากระโดด) และติดตามสถานะการเชื่อมต่อ
- [`src/net/net_retry.c`](src/net/net_retry.c) เป็นนโยบายการลองใหม่
  รอ 1/2/4/8 วินาที รวมไม่เกิน 45 วินาที และลองทันทีเมื่อ Wi-Fi กลับมา
- [`src/ui/net_task.c`](src/ui/net_task.c) แสดงสถานะ "Reconnecting…" ระหว่างรอ
  และลองโหลดใหม่ให้เอง
- ข้อผิดพลาดที่มาจาก YouTube เอง หรือกรณียังไม่ได้ล็อกอิน จะไม่ลองใหม่


ส่วน `test_dl_core` ต้องคอมไพล์ jansson (ใน `external/jansson`) แยกก่อน ขั้นตอนเต็มอยู่ใน
[`.github/workflows/build.yml`](.github/workflows/build.yml)

- `test_dl_core` ทดสอบระบบดาวน์โหลดกับการ์ดจำลองและเซิร์ฟเวอร์ YouTube จำลอง:
  โหลดจนจบ, หยุดแล้วต่อกลางช่วง, เน็ตขาดกลางช่วงแล้วต่อจากไบต์เดิมโดยข้อมูลไม่ซ้ำไม่ขาด,
  URL หมดอายุ, redirect, สถานะ 200/206/416/403/404/410/429/5xx, ที่ว่างไม่พอ, การ์ดเต็มกลางทาง,
  ไฟล์ MP4 เสียแบบต่างๆ, ไฟล์ index เสียหรือถูกใส่ id อันตราย (เช่น `../x`), เครื่องดับกลางทางแล้วเปิดใหม่,
  ลบระหว่างโหลด, และการหยุดรอตอนดูวิดีโอออนไลน์
- `test_local_stream` ตรวจการอ่านและการกรอของไฟล์ในการ์ด รวมไฟล์ใหญ่กว่า 4 GB
- `test_dl_format` ตรวจการแสดงขนาดไฟล์ ความเร็ว และเปอร์เซ็นต์
- `test_parse`, `test_innertube` และ `tests/ui_paging/` ตรวจการโหลดต่อ: parser กับ response จริง (หน้า 1–4 ของ Start,
  ช่อง, ค้นหา), คำขอที่ส่งออกจริงของ `innertube.c` ต่อ surface (endpoint, client, ตัวกรอง, visitor header),
  และ 26 สถานการณ์บน `list_screen_run` จริง (กดค้าง ล้มเหลวติดกัน ยกเลิก ถึง 240 แถว สลับบัญชีหรือภูมิภาค)
  โค้ดทดลองที่ฝังบั๊กไว้ 106 แบบถูกจับได้ 97 แบบ ที่เหลือเทียบเท่ากันหรือซ้ำซ้อนกับการตรวจอื่น

- `test_thai_shape` ตรวจทุกแถวในตารางที่สร้างไว้ ทั้งเมื่อข้อความอยู่ติดกับข้อความอื่น
  ข้อความที่ไม่ใช่ภาษาไทยต้องผ่านไปโดยไม่เปลี่ยน UTF-8 ที่ถูกตัดกลางคันต้องไม่ทำให้อ่านเกินขอบ
  และผลลัพธ์ต้องไม่ยาวกว่าข้อความเดิม
- `test_kinetic_scroll` ตรวจว่ารายการเลื่อนตามนิ้ว 1:1 แยก tap กับการลากได้ถูก
  การไหลต่อหลังปล่อยนิ้วค่อยๆ หยุด การเด้งกลับที่หัวท้ายรายการ การเลื่อนด้วย D-pad
  และให้ผลเหมือนกันทั้งที่ 30 และ 60 fps
- `test_net_retry` ตรวจระยะเวลารอระหว่างการลองใหม่ เพดานเวลาและจำนวนครั้ง
  การลองทันทีเมื่อ Wi-Fi กลับมา และการตรวจจับว่าเครื่องเพิ่งตื่นจากโหมดพัก

## Build

ทุกครั้งที่ push จะมี [GitHub Actions](.github/workflows/build.yml)
build VPK ด้วย Docker image ของ VitaSDK แล้วแนบไฟล์ไว้ใน artifact ของ run นั้น
ถ้า push tag ที่ขึ้นต้นด้วย `v` จะสร้าง Release พร้อมไฟล์ `ViTube-TH.vpk` ให้ด้วย

ถ้าจะ build เอง ทำตามขั้นตอนใน [README ต้นฉบับ](README.upstream.md#build) ได้เลย
(ต้องมี VitaSDK และ build FFmpeg กับ curl ก่อน)
